# Private request diagnostics and synthetic capacity evidence

This change records request performance without recording a child's identity,
PIN, token, utterance, recording, URL query, IP address, user agent or referrer.
`X-Request-Id` is generated by the server; an incoming value is ignored. It is a
correlation identifier, never an authorization credential. Browser CORS exposes
it alongside the existing KG feedback receipt; allowed origins are unchanged.

The `HTTP request completed` JSON event contains a static Express route template,
an allowlisted API area, method, status, duration and disconnected flag. Unmatched
paths are represented by `[unmatched]`. Correlate a request failure with its
generated ID. Provider exception messages/stacks can contain echoed child text,
so the HTTP error boundary and modified Azure/OpenAI/Python paths record fixed
categories/status instead. Warmup warnings omit student IDs. This does not
certify every optional historical provider or infrastructure log/retention
configuration; inspect the actual ingress and deployed logging destination.

Useful operational views: p50/p95 by area/template, 429/5xx rates, disconnects,
and the existing KG stage timing/receipt recovery reports. Aggregate over
meaningful windows and suppress low-volume learner-identifiable breakdowns.
Provider readiness, physical playback, native-language quality and budget
alerts require deployment/provider evidence; `/health` remains liveness only.

The Python bridge now starts its timeout only after validating production
service authentication. Previously a rejected configuration left a live timer
outside the `finally` block. The security check still fails closed; no service
key, transcript or upstream response is logged.

## Reproduce local capacity checks

Install the existing dev dependencies; no new packages are required. This runner
creates its own loopback server and disposable MongoDB, and accepts no external
URL, real school credentials, token file or MongoDB connection string.

```bash
cd backend
NODE_ENV=test TALKORA_SHARED_RATE_LIMITS=true TALKORA_SYNTHETIC_LOAD_ACK=LOCAL \
  pnpm exec tsx src/scripts/profile-synthetic-kg-load.ts
```

On hosts where the tsx CLI's IPC socket is unavailable, run `pnpm build` then
`node dist/scripts/profile-synthetic-kg-load.js` with the same environment.
`TALKORA_SYNTHETIC_REPORT` optionally selects a local JSON output file.
Accounts are bounded to 100–10,000 and requests per stage to 100–3,000. Only the
database created by this process can be dropped during cleanup.

## Measured on 10 November 2026

10,000 synthetic enrolled KG accounts across two synthetic schools; one Node
process (server **and** generator), MongoDB 7.0.14, atomic Mongo rate-limit store,
600 authenticated read-only overview requests per stage. Request logging enabled.

| Concurrent reads | Requests/s | p95 ms | Errors | Node peak RSS MiB | Mongo resident MiB after |
| --- | --- | --- | --- | --- | --- |
| 1 | 176.4 | 8.0 | 0/600 | 404 | 193 |
| 10 | 305.3 | 38.3 | 0/600 | 434 | 194 |
| 30 | 340.1 | 100.9 | 0/600 | 468 | 198 |
| 60 | 371.6 | 205.2 | 0/600 | 511 | 206 |

The Node memory figure includes seeding, the in-process generator, client
connections and server work. Increasing memory across these short stages is
not proof of a leak or a stable long-session memory bound. Run a separate soak
test before release. Throughput flattens while latency rises; profile the
generator/Node CPU, database operations and limiter costs with separate load
hosts before sizing replicas. This is **not** production capacity, a 10,000
concurrent-session result, PIN/NAT burst acceptance, or voice latency. No STT,
Qwen, TTS, S3, microphone, speaker or production endpoint was used. Real TLS,
proxy trust, school networks, provider quotas/costs and multi-process deployment
remain unverified.

## Review and rollback

Privacy regression tests inject synthetic canaries into paths, queries, headers,
request bodies, provider errors and exception messages; none may reach these
logs. Existing KG, Class 1, provider and authorization CI remains required.
No schema/data migration, production operation, publication or dependency
upgrade is included. Revert the code to roll back; no progress rollback exists
or is needed. A rollback to legacy URL logging requires an explicit privacy
review before handling real children's traffic.
